# あらいコーチ 問題データ更新ガイドライン

過去の令和1年〜6年分(808問)のデータ整備で実際に発見・修正した問題パターンを
体系化したもの。今後、新しい年度(令和7年など)のPDFを追加する際は、
このガイドラインをGensparkへの指示に添付することで、これまでと同じ品質基準・
言い回しで齟齬なく更新できる。

## 0. データ構造(exam_questions.json)

```json
{
  "id": "q_type1_R7年4月_1",           // q_{タイプ}_{年度}_{問番号}
  "examType": "type1",                  // type1=第一種, type2=第二種
  "year": "令和7年4月公表",
  "categoryKey": "law_harm",
  "categoryName": "関係法令(有害)",
  "subCategory": "",
  "format": "choice5",                  // 5択 or 穴埋め等
  "number": "問1",
  "text": "問題文...",
  "items": [],                          // 穴埋め問題の場合、穴埋め表の各行
  "choices": ["(1) ...", "(2) ...", "(3) ...", "(4) ...", "(5) ..."],
  "correctIndex": 4,                    // 0始まり
  "aiExplanation": "あらいコーチ口調の解説",
  "officialExplanation": "客観的な公式解説"
}
```

**重要な特性**:
- 第一種(type1)と第二種(type2)は共通問題が多い(同一問題文がq_type1側とq_type2側の両方に存在)。
  **片方だけ修正して他方を直し忘れるミスが過去に複数回発生している**ため、
  1つの誤りを見つけたら必ず `grep` 等で同一テキストパターンを全件検索し、
  重複問題も同時に修正すること。

## 1. PDFからのデータ抽出時に発生しやすい問題(過去の実例)

PDFのOCR/コピペ抽出由来で、以下のパターンが繰り返し発生していた。
新しい年度データを取り込む際は、下記チェックリストで機械的にスキャンすること。

### 1-1. 文字化け・誤変換(OCR起因)

| 誤 | 正 | 備考 |
|---|---|---|
| ボウマのう こン嚢 / ボウマのう こン囊 | ボウマン嚢(のう) | 腎臓問題で繰り返し発生 |
| ｶﾊﾞｰ、ｸﾞﾛｰﾌﾞﾎﾞｯｸｽ 等の半角カタカナ | カバー、グローブボックス 等の全角カタカナ | U+FF66-FF9Fの半角カタカナを網羅チェック |
| ｡｢｣･ 等の半角句読点 | 。「」・ 等の全角 | 半角カタカナと同時に混入しやすい |
| 「粉しん」「一決予防」「なんんだ」「びょう機」等の単純誤字 | 「粉じん」「一次予防」「なんだ」「びょう機」等 | 1文字誤変換。全文検索で類似パターンも洗い出す |
| 「¥u0000」「○んだ」「SAんだ」等の文字化け残骸 | 削除 | コピペ時の制御文字混入 |
| 「1回○ 換気量」「ＡＴＰにたん蓄えられた」等、余分な1文字混入 | 該当文字を削除 | PDF抽出時のノイズ |
| 全角/半角混在(A/Ａ、B/Ｂ等の組合せ選択肢ラベル) | 全角に統一(Ａ,Ｂ,Ｃ,Ｄ,Ｅ) | **ただし** WBGT/BMI/ATP/ADP/BUN/PCB/A1c/dB/COPD/AED/METs/LDL/HDL/CRS/PDCA/PC等の技術略語・固有名詞に含まれる半角英字は変換対象外 |

### 1-2. 空白・改行・記号の不整合

- **半角スペースの混入**: 「対 しては」「原料を反応槽へ○○」のような単語途中の余分な半角/全角スペースを削除
- **全角スペースの過不足**: 選択肢Ａ〜Ｄの前に付与する全角スペースの有無が不統一な箇所は、他の選択肢と揃える
- **「・・・・・・」等の意味のない繰り返し記号**: 表組みレイアウトの罫線・空白残骸として混入することがあるため削除
- **改行位置**: 以下のルールで統一する(2025/8のコミットで全808件に適用済みの実績ルール)
  - **問題文(text)**: 句点(。)ごとに改行。選択の前提となる数値リスト等は項目ごとに改行
  - **AI解説(aiExplanation)**: 冒頭「正解は(N)だよ。」の直後で改行し、以降は句点ごとに改行
  - **公式解説(officialExplanation)**: 選択肢マーカー(（1）〜（5）、Ａ〜Ｅ)が2つ以上ある場合は句点改行+マーカーごとの改行を併用。それ以外は句点改行のみ
  - 句点直後に閉じ括弧・空白がある場合はスキップしてその後で改行(括弧の途中で改行しない)
  - 「→」「※」「・」など記号のみの行は次の行と結合し、孤立させない
- **選択肢データの欠落・崩れ**: 「1か月以内ごとに1回」のような区切り文言が選択肢内で失われていないか、原本PDFと突合して確認する

### 1-3. データ欠落・構造崩れ

- 選択肢の一部テキストが丸ごと欠落(例:測定頻度の記載が抜けている)していないか、5択すべてが原本と一致するか必ず突合する
- 括弧の片方だけ抜けている(例:「炭水化物(糖質」のように閉じ括弧なし)ケースがあるため、開き括弧と閉じ括弧の対応数を機械チェックする

### 1-4. PDF改ページ・レイアウト崩れに起因する問題(重要・頻出)

PDFは「ページの区切り」や「表組みレイアウト」の情報を持たないテキストとして
抽出されるため、以下の3パターンが**過去に何度も**発生している。新年度データの
取り込み時は、この3点を必ずチェックすること。

**① 表組みデータが1行のtextに詰め込まれてしまう問題**

PDF上では見出し行とデータ行が「表」として視覚的に分かれているが、
テキスト抽出すると改行が失われ、過剰なスペースで無理やり区切られた
1本のテキストになってしまう。(`c076d7f` で19件修正した実績あり)

```
# 誤(抽出直後): 見出しと本文が同じ行に混在
"ヒトのホルモン、その内分泌器官及びそのはたらきの組合せとして、誤っているものは
 次のうちどれか。ホルモン         内分泌器官            はたらき"

# 正: 本文と見出しを改行で分離し、過剰スペースを正規化
"ヒトのホルモン、その内分泌器官及びそのはたらきの組合せとして、誤っているものは
次のうちどれか。\nホルモン　内分泌器官　はたらき"
```

- 年齢別重量表・精密検査結果表のように行データが複数ある場合は、
  文字列のまま整形するのではなく **`items` 配列に変換**し、
  「年齢→断続作業:X 継続作業:Y」のような構造化した形にする
  (令和3年10月・令和6年10月の重量物取扱い問題などで実績あり)。

**② ページ終端マーカーが選択肢末尾に混入する問題**

PDF原本のページ最後に印字されている「（終り）」「（終　り）」等の
ページ終端マーカーが、そのまま選択肢(5)の末尾にくっついて抽出されてしまう。
(`047d671` で生理学系18問・type1/type2ペアを修正した実績あり)

```
# 誤
"(5) メラトニン　松果体　睡眠の促進（終　り）"

# 正
"(5) メラトニン　松果体　睡眠の促進"
```

- チェック方法: 選択肢テキストに「終り」「終　り」等の残骸パターンが
  含まれていないか全件検索する。

**③ 改行で分割された単語の結合時に余分なスペースが残る問題**

PDF内で1つの単語・数値が行末で改行され、テキスト抽出時に単語を
結合する際、境界に半角/全角スペースがそのまま残ってしまう。
(`942a5d2` で587問・officialExplanation中3046箇所を機械的に修正した実績あり)

このときは、闇雲に全スペースを削除するのではなく、以下の**3分類**で
安全に処理すること:

| 分類 | 条件 | 処理 |
|---|---|---|
| PERIOD | 「正しい」「誤り」「よって」等の判定語の直後のスペース | 句点(。)に変換する(46件) |
| MERGE | 数字と単位、単語の途中など、改行結合由来と判断できる箇所のスペース | 削除して単語をつなげる(3046件) |
| SKIP | 選択肢マーカー・表・数式記号の近く等、削除すると意味が変わるリスクがある箇所 | **削除せず現状維持**(1004件、安全側に倒す) |

```
# 誤(改行結合由来のスペースが数字・単位の間に残存)
"（5） 【500 人】以上を深夜業を含む有害業務に従事させる事業場では産業医を
【専属】させる 必要があるが、この事業場は 300 人のため専属の産業医は不要。"

# 正
"（5） 【500人】以上を深夜業を含む有害業務に従事させる事業場では産業医を
【専属】させる必要があるが、この事業場は300人のため専属の産業医は不要。"
```

- **判断に迷う場合はSKIP(現状維持)を優先**する。過去の作業でも
  「削除して良いか判断できないスペースは触らない」という安全側の
  方針で1004箇所を意図的に残した実績がある。

## 2. AI解説(aiExplanation)の文体ルール(「あらいコーチ」口調)

「あらいコーチ」はアライグマのキャラクターで、一人称は「僕」、口調は親しみやすい
「だよ・だね」調のくだけた話し言葉。以下は実際に何度も往復修正して固まったルール。

### 2-1. 基本フォーマット
```
正解は(N)だよ。
{誤りの選択肢の内容を引用}という記述が誤りなんだ。
{必要であれば補足説明}
他の4つの選択肢はすべて正しい内容だよ。
```
※「正解は(N)だよ。」の1文目は改変しない(定型文として扱う)。

### 2-2. 禁止・回避すべき表現(すべて過去に指摘され修正済み)

| NG表現 | 修正後 | 理由 |
|---|---|---|
| 「(N)の内容が問題のポイント。」 | 削除 | 意味のない前置き・冗長 |
| 「各項目を1つずつチェックして正誤を判断しよう。」 | 削除 | 組合せ問題の末尾に付いていた意味のない締め文 |
| 「〜が正しいルールなんだ。」 | 「〜が正しいよ。」 | 不自然な言い回し。全149箇所修正した実績あり |
| 「〜が正しいよ。」(短すぎる場合) | 「〜が正しい内容だよ。」 | より自然な言い回しに統一(149件) |
| 「調節するだよ」「高いだよ」等、動詞・形容詞終止形に直接「だよ/だね」を接続 | 読点を挿入:「調節する、だよ」「高い、だね」 | 日本語として不自然(38件修正実績) |
| 「〔労働生理だよ〕。」等の無意味な科目ラベル付記 | 削除 | 解説として無意味 |
| 文末が「〜んだ。」「〜だね。」だけで主語や内容が欠落した断片 | 前後の文脈から完全な文に書き直す | 「職務んだ。」「×だよ。」等の破損文 |
| 選択肢の引用が「0.4m」等、数値の途中で切れている | officialExplanationを参照し文末まで補完 | 200文字上限による強制切り捨てバグに起因(72件発生) |
| 「なんんだ」(二重誤字) | 「なんだ」 | タイプミス系、要全件検索 |
| 穴埋め問題で「Ａ：馬尿酸Ｂ：鉛Ｃ：尿だよ」のようにカンマなし羅列 | 「Ａ：馬尿酸、Ｂ：鉛、Ｃ：尿だよ」 | 読点で区切り読みやすくする |
| 穴埋め問題の解説が単語の列挙のみ(例:「Ａ：馬尿酸、Ｂ：鉛、Ｃ：尿だよ。」で終わる) | 可能な限り「〜については［Ａ:馬尿酸］を測定し、〜」のような**ナラティブ(文章)形式**に書き直す | 短すぎる解説は分かりにくいため、後から19件以上をナラティブ化した実績あり |

### 2-3. 文字数の目安
- aiExplanationは**200文字程度を上限の目安**とする(旧実装で200文字超は強制的に「…」で切り捨てられるバグがあったため、それに引きずられて不完全な文が大量発生した経緯がある)。
- 長くなる場合は要点を絞り、「他の4つの選択肢はすべて正しい内容だよ。」等で締める。

---

## 3. 公式解説(officialExplanation)のルール

- 各選択肢を（1）（2）（3）…の形式で1行ずつ、正誤とその理由を簡潔に記載
- 正しい選択肢は「正しい」、誤りの選択肢は誤りの理由を【】で強調(例:「【500人】以上を…」)
- 客観的・事実ベースの記述とし、aiExplanationのような「だよ・だね」口調は使わない
- 数値や法令の単位表記(㎥、mSv等)は統一する(「150m3」ではなく「150㎥」)

---

## 4. 選択肢・問題文の整形ルール

- 5択は `(1) 〜` 〜 `(5) 〜` の半角括弧+半角数字で統一
- 組合せ問題のアルファベットラベル(Ａ〜Ｅ)は全角で統一(技術略語中の半角英字は除く。1-1節参照)
- 数値の桁区切りや単位(kg, ㎥, mSv等)は既存問題の表記に合わせる
- 業務内訳等の箇条書きは「深夜業を含む業務：300人」のように全角コロン区切り+改行で統一(他年度の同形式問題と表記を揃える)

## 5. 法改正による過去問の内容変化への対応(重要)

衛生管理者試験は「出題当時は正しかった内容」が、その後の法改正で
「不正確」「正答が変わる」「そもそも成立しない問題になる」ことがある。
本アプリは**出題当時の過去問をベースに収録**しているため、
法改正が発覚した際は以下のいずれかの方法で対応する。実際に過去、
811問→808問への調整(3問除外)と、複数問題での正答複数化対応を行った実績がある。

### 5-1. 対応方針の判定フロー

法改正の影響を受けている問題を発見したら、まず「正答がどう変化するか」で
以下の3パターンに分類する。

| パターン | 状態 | 対応方法 |
|---|---|---|
| A. 正答は変わらないが、問題文・選択肢の記述が古い | 現行法令では表現が変わっただけで、正誤判定自体は変わらない | **問題文・選択肢を現行の記述に修正**し、解説に改正の経緯を注記する(5-2) |
| B. 法改正により正答が2つ以上になる | 出題当時は1つの正答だったが、改正で別の選択肢も正しくなった(または誤りでなくなった) | **`correctIndexes`(複数正解)で対応**する(5-3) |
| C. 法改正により正答が0個になる、または問題として成立しなくなる | 改正によりすべての選択肢が誤りになる、または前提条件自体が崩れる | **問題を完全に除外(削除)する**(5-4) |

**判定に迷う場合の考え方**: 「今の法令で全選択肢を判定し直したときに、正しい(誤りを問う問題なら誤りの)選択肢が何個になるか」を基準にする。1個ならA、2個以上ならB、0個(またはそもそも問題文の前提が崩れる)ならC。

### 5-2. パターンA: 記述だけ更新し正答は変えない場合

**実例(`ad877dc`)**: 衛生管理者の選任報告に関する問題で、出題当時の選択肢は
「所定の様式による報告書を…提出しなければならない」だったが、2025年1月の
法改正で電子申請が義務化されたため、選択肢の記述自体を現行内容に修正した
(正答は(1)のまま変わらず)。

```json
// 修正前(出題当時のまま)
"choices": ["(1) 衛生管理者を選任したときは、遅滞なく、所定の様式による報告書を、所轄労働基準監督署長に提出しなければならない。", ...]

// 修正後(現行法令に合わせて選択肢を書き換え)
"choices": ["(1) 衛生管理者を選任したときは、電子情報処理組織を使用して、資格を証明する電磁的記録を添えて、所定の事項を所轄労働基準監督署長に、遅滞なく報告しなければならない。", ...]
```

- `officialExplanation`の該当選択肢の末尾に、**必ず改正の経緯を注記**する:
  ```
  ※本問は、公表後に法令が改正されたので、問題文(選択肢(1))を一部修正している。
  本問公表時には「〜」となっていたが、その後、〜(具体的な条文・規則名)が改正され、
  〜(改正後の内容)とされたため、選択肢を現行の内容に修正した。正答は変わらず(1)。
  ```
- `aiExplanation`側にも、だよ口調で同様の注記を追記する(例:「※出題当時、選択肢(1)は「〜」となっていましたが、その後の法改正(〜)により、現在の内容に選択肢が修正されています。正答は変わらず(1)です。」)
- correctIndex/correctIndexesは変更しない。

### 5-3. パターンB: 正答が複数になる場合(`correctIndexes`フィールドを使用)

`Question`モデル(`lib/models/question.dart`)には、法改正で正答が複数になった
問題専用のフィールドとして **`correctIndexes`(int配列、0始まり)** が既に実装済み。
通常の問題ではこのフィールドは付与せず、`correctIndex`(単数)のみを使う。
法改正で複数正解になった問題にだけ、追加でこのフィールドを付与する。

**実例(`q_type1_R2年10月_3`, `q_type1_R2年4月_2`)**: 「作業主任者の選任が
義務付けられている作業はどれか」という問題で、出題当時の正答は(2)硝酸の
洗浄作業のみだったが、令和4年4月1日施行の安衛令改正で「溶接ヒュームを
製造・取扱う業務」も特定化学物質作業主任者の選任対象となったため、
(1)アーク溶接の作業も正答に追加された。

```json
{
  "correctIndex": 1,           // 出題当時の元々の正答(後方互換性のため残す)
  "aiExplanation": "正解は(2)だよ。\n硝酸は特定化学物質(第三類物質)だから、製造工程で硝酸を用いて行う洗浄の作業には特定化学物質作業主任者の選任が必要なんだ。\nただし、現在の法令では(1)の屋内作業場におけるアーク溶接の作業も選任対象になっているから、出題当時の正答は(2)でも、法改正後はそのままでは正答が複数になる点に注意だよ。",
  "officialExplanation": "(1) 出題当時は義務付けられていなかったが、安衛令別表第三の改正により、令和4年4月1日より「溶接ヒュームを製造し又は取り扱う業務」について「特定化学物質作業主任者」の選任を要することとなった。従って、現在はアーク溶接の作業についても作業主任者の選任が必要。\n(2) 義務付けられている。硝酸は特定化学物質(第三類物質)であり、洗浄の作業は「特定化学物質作業主任者」の選任が必要。\n(3)〜(5) 義務付けられていない。\n出題当時の正答は(2)のみでしたが、本問出題後の安衛令改正(溶接ヒュームの特定化学物質指定、令和4年4月1日施行)により、現在は(1)(2)の2つが正答となります。",
  "correctIndexes": [0, 1]     // ★追加: 現行法令での正答をすべて列挙(0始まり)
}
```

**ポイント**:
- `correctIndex`(単数)は出題当時の元の正答のまま変更しない(後方互換性・過去の実績記録のため)。
- `correctIndexes`配列に、**現行法令で正しい選択肢のインデックスをすべて**列挙する(0始まり であることに注意。選択肢(1)→0、選択肢(2)→1)。
- `officialExplanation`には、各選択肢の当時/現在の判定の違いと、「出題当時の正答は◯のみでしたが、法改正により現在は◯◯の2つが正答となります」という結論を明記する。
- `aiExplanation`にも同様の注意喚起をだよ口調で追記する。
- アプリ側は`Question.allCorrectIndexes`/`isCorrectAnswer()`が自動的に`correctIndexes`を優先参照するため、UI・採点ロジックの追加実装は不要(既存の全画面で対応済み)。

### 5-4. パターンC: 問題自体を削除(完全除外)する場合

法改正により、選択肢を書き換えても正答が成立しなくなる(全選択肢が誤り/正しいに
揃ってしまう等)場合は、問題ごと`exam_questions.json`から削除する。

**実例(`exclude_new_3.py`)**: `q_type2_R2年4月_6`、`q_type2_R3年4月_6`、
`q_type2_R4年4月_6`の3問(いずれも「雇入れ時の安全衛生教育」に関する類似問題)は、
省令改正により出題当時のままでは正答が複数になる、または正答が0個になって
しまうことが判明したため、選択肢の一部修正では対応しきれないと判断し、
問題を完全に削除した(811問→808問)。

```python
# 削除の実施例(law_revision_check/exclude_new_3.py を参考にしたパターン)
import json

EXAM_PATH = "/home/user/flutter_app/assets/data/exam_questions.json"
TARGETS = {"q_type2_R2年4月_6", "q_type2_R3年4月_6", "q_type2_R4年4月_6"}  # 削除対象のid

with open(EXAM_PATH, encoding="utf-8") as f:
    data = json.load(f)

before = len(data)
removed = [q["id"] for q in data if q.get("id") in TARGETS]
data = [q for q in data if q.get("id") not in TARGETS]

assert set(removed) == TARGETS, "削除対象が一致しません"
print(f"Before: {before} -> After: {len(data)} (removed: {removed})")

with open(EXAM_PATH, "w", encoding="utf-8") as f:
    json.dump(data, f, ensure_ascii=False, indent=2)
```

**削除する際の注意点**:
- **type1/type2で共通の問題**の場合、片方だけ削除して他方を消し忘れるミスが起きやすいため、削除前に必ず同一問題文パターンで`grep`し、両方を洗い出してから削除する。
- 削除は**必ずユーザーの承認を得てから実行**する(過去の実績でも「グループB」「ユーザー承認済みの方針」といった形で事前確認を取った上で除外している)。単独の判断で無断削除しない。
- 削除後は必ず問題総数(`len(data)`)が想定通り減っているかをassertで検証する。
- 削除後は`build_master_data.py`でマスターExcelを再生成し、削除件数が反映されているか確認する。

### 5-5. 法改正チェックの進め方(推奨フロー)

1. 新しい年度のPDFを取り込む際、または既存問題に対する法改正情報を受け取った際、
   まず該当問題の**出題年**と**該当法令・条文**を特定する
2. 出題年時点の条文・基準と、現行の条文・基準を比較し、選択肢の正誤判定が
   変わっていないか1つずつ確認する
3. 上記5-1の判定フロー(A/B/C)に従って対応方針を決定する
4. パターンB・Cの場合は、**対応方針をユーザーに提示し承認を得てから**実データを変更する
5. 変更後は`officialExplanation`と`aiExplanation`の両方に改正の経緯を明記する(法改正の事実を消さず、「なぜ変わったか」を学習者が理解できるようにする)
6. type1/type2の重複問題がないか確認し、両方に同じ対応を適用する
7. `build_master_data.py`でマスターExcelを再生成し、変更を反映する
